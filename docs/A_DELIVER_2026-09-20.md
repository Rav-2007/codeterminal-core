### A3.4 The two failures, and why they are the job earning its place


**(M) Failure 1 — `TestHelperAddressIsScopedByDaemonPID`: the production value is
correct and the assertion is wrong by one backslash.** The test checked
`strings.HasPrefix(addr, ` + "`" + `\.\pipe\` + "`" + `)`; the Windows named-pipe namespace,
and `protocol`'s own `pipePrefix` at `protocol/transport_windows.go:38`, is
`` `\\.\pipe\` ``. The assertion **could not pass on the only platform that reaches
it.**

The clinching detail is that **the same assertion exists in `protocol` and is
correct there**: `protocol/transport_test.go:137` reads `` `\\.\pipe\` ``. Two copies
of one constant, in two modules — and the copy in the module that has been in the
Windows matrix is right, while the copy in the module that has never been in it is
wrong. That is the thesis of adding `helper` to the matrix, demonstrated on the
matrix's first run rather than argued.

**(M) Failure 2 — `TestHandleConnAuthorizesThenServes`: the accommodation,
surviving in a second place.** The test called `net.Listen("unix", …)` and
`net.Dial("unix", …)` against a `.sock` file in `t.TempDir()`. Go supports AF_UNIX
on Windows 10 1803+, so those calls **succeed** there — and the test then drives a
transport production never uses, against a peer-auth path with no credentials to
read on that socket type. Hence "forcibly closed".

This is the **same shape**, and it survived **two** commits that each removed
another instance of it:

- `666ae2d` removed it from `daemon/testdata/fakehelper/main.go`.
- `43e17bc` removed it from `helper/recover_test.go` — **in this same

  Windows matrix.

touched it. Two separate opportunities to sweep one small module for one known
shape, and neither sweep happened. **That is the fifth instance in this pass of
correcting a shape where it was seen rather than where it repeats**, and the
second one that shipped.

*(An earlier draft of this section said `666ae2d` fixed both files. It did not —

## A8 — the release the tag would not have made

Phase 3 of the release plan is a `workflow_dispatch` rehearsal on canonical,
written down as "the step that de-risks everything after it". It was not reached.
Reading `release.yml` to write the rehearsal's prediction found the thing the
rehearsal existed to find.

### A8.1 The defect

`.github/workflows/release.yml`, `package` job, step `Stage the terminal client`:

```bash
for TARGET in linux-x64 win32-x64; do
  ...
  cp -a "$SRC" "out-bin/codeterminal-tui-$TARGET$EXE"
done
N=$(find out-bin -type f | wc -l)
[ "$N" -eq 3 ] || { echo "::error::staged $N terminal-client binaries, expected 3"; exit 1; }
```

Two iterations, three demanded. **(M)** — the step extracted verbatim from
`HEAD` and run under `bash -e -o pipefail`, which is how Actions invokes
`shell: bash`, against two fixture binaries:

```
::error::staged 2 terminal-client binaries, expected 3
OLD_STAGE_RC=1
```

`Stage the terminal client` precedes `Checksums`, the `terminal-client` and
`vsix-packages` uploads, `Signing guard` and `Attach to the GitHub Release`. A
`v0.0.2` tag would have failed there and **published nothing on any platform**.

### A8.2 Why it was there, and why nothing caught it

`43e17bc` ("ship Linux and Windows only — **a tag now publishes instead of
nothing**", 2026-09-17) removed `darwin-arm64`. Its diff against
`.github/workflows/release.yml` is exactly two lines:

```
-          for TARGET in linux-x64 darwin-arm64 win32-x64; do
+          for TARGET in linux-x64 win32-x64; do
-          for TARGET in linux-x64 darwin-arm64 win32-x64; do
+          for TARGET in linux-x64 win32-x64; do
```

Both loops moved. The `3` did not, because a `3` is not a target name and
nothing in the repository was looking for one. The commit that says a tag now
publishes instead of nothing left a tag publishing nothing, for a different
reason, in the same file, in the same change.

Nothing has run it since. **(M)** `gh run list --workflow release.yml` on
canonical returns **one row in the workflow's entire existence**:
`31505527398`, event `push`, 2026-08-11, at `bd1bc69`, conclusion **failure**.
Every green release rehearsal is on the fork and predates 2026-09-17, when the
`3` was still correct.

This is the brief's third named failure mode, in its purest form: *counts are
wrong by default; derive every count from an enumeration in the same breath,
never carry one forward.* The count was correct when written and became wrong
without being touched.

### A8.3 The fix is not a corrected number

Writing `2` would leave the same defect with a later expiry date. The count is
now accumulated in the loop body — it cannot drift from the enumeration because
it **is** the enumeration:

```bash
EXPECT=0
for TARGET in linux-x64 win32-x64; do
  ...
  EXPECT=$((EXPECT + 1))
done
N=$(find out-bin -type f | wc -l)
[ "$N" -eq "$EXPECT" ] || { echo "::error::staged $N terminal-client binaries, expected $EXPECT"; exit 1; }
```

Assignment form, not `((EXPECT++))`: the latter returns 1 when the old value is
0, and `set -e` turns that into a dead job on the first iteration. The literal
target names stay, so `target-parity.sh` still binds the loop to
`scripts/release-targets.txt`. The two gates compose — parity ties the loop to
the source of truth, this ties the count to the loop.

**(M)** The fixed step, same harness, same fixtures:
`staged 2 terminal-client binaries (one per target in the loop)`, rc **0**.

### A8.4 The gate that should have caught it, and now does

`target-parity.sh` exists precisely for this removal — its header says "dropping
`darwin-arm64` on 2026-09-17 meant editing all five". It was green throughout.
It compares **lists**: the matrix, both `for TARGET in` loops, and
`stage-runtime.js`'s regex. A count is a mirror of the target set that it
**structurally cannot compare**, because a stale `3` and a correct `2` are both
just integers.

So mirror 5 is enforced by **absence**: `release.yml` must hard-code no count
threshold `>= 1`, and must derive one from the loop it counts. `-eq 0` and
`-ne 0` stay legal — a zero is an exit-status check, not a tally, and a gate
that taxes every `|| exit` in the file is a gate the next person deletes.

**(M)** Demonstrated failing on the **real artifact**, not only a fixture — the
gate run against `HEAD`'s `release.yml`:

```
target-parity: FAIL: release.yml hard-codes a count. Derive it from the loop instead.
    319:          [ "$N" -eq 3 ] || { echo "::error::staged $N ... expected 3"; exit 1; }
```

Self-test: **14 arms**, was 10. Arm `n10` uses the real literal verbatim.

### A8.5 The gate forbade documenting itself

The comment written into `release.yml` explaining all of the above **failed two
mirrors on its own text**. `grep -h 'for TARGET in'` matches comments, so the
prose was parsed as a third loop and the mismatch listed the comment's own words
as target names (`#`, `edited`, `BOTH`, `loops`, `three`, `names`…); and mirror
5 matched the quoted `` `-eq 3` `` at line 309.

That is a pre-existing fragility the comment merely exposed — before it, no
comment in the file's history had ever contained the string. Both scanners now
skip whole-line comments. Rewording around it was the other option and is the
wrong one: a gate that cannot be described in prose beside the thing it guards
gets worked around rather than fixed.

Two arms added for it, green in both mirrors, and both **failed before the
hardening**. Trailing comments on code lines are deliberately not handled —
deciding whether a `#` is a comment or a character in a string means guessing,
and guessing wrong makes the gate fail on correct code. The script says so.

### A8.6 And the prose carried the same stale three

`43e17bc` swept the code and not the file. Six live claims still said three:
the `binaries` hypothetical ("runs on all three runners"), "CI already has all
three runners green", "three copies of a 7.5 MB binary … is 22 MB", "One Linux
runner assembles all three packages", the step name **"Package all three
targets"**, and "This loop packages all three targets on ONE Linux runner". All
six corrected. The three surviving `three`s are history — a three-platform era,
three jobs, three version sources — and are correct.

*An accommodation survives the sweep that removes its siblings.* So does a
number, and so does a sentence.
