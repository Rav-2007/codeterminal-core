### The fact the row rests on, re-established rather than carried

`TestPersistTurn_NilConfigScrubsRatherThanSkips` builds a `Server` with `cfg` deliberately nil and
passes in **0.04 s** DETERMINISTIC **(M)**. So a `Server` **can** exist with a nil config, and the

**What that does not show, and the register row should say so.** Both production constructors set

sites with a nil config today.** This is consistency and fail-closed-by-construction, not a live
incident, and inflating it would be the easier and worse report.

**Why it was still worth the commits.** `daemon/context.go:322` is the accessor:

landing. A direct field read cannot invert, but it is the raw material an inversion is made from,
and leaving exactly one expression in the package that names the field is what stops a third
occurrence.

## Row 4 — the LSP retraction, filed as a negative result with equal weight

**A report listing only findings reads as though everything examined was broken.** This one was
examined and is fine.

A prior session accepted, then correctly retracted, a reachability inversion placing LSP above MCP.
The retraction's basis, verified at HEAD — `daemon/lsp_bridge.go:156` **(M)**:

```go
func serverCommand(lang editapply.Language) (string, error) {
	switch lang {
	case editapply.LangGo:
		return "gopls", nil
	case editapply.LangTypeScript, editapply.LangJavaScript:
		return "typescript-language-server", nil
	case editapply.LangPython:
		return "pyright-langserver", nil
	default:
		return "", fmt.Errorf("unsupported language for LSP: %s", lang)
	}
}
```

**Three hardcoded names, resolved on the inherited `PATH`.** Attacker-authored *source* cannot choose
which binary runs, so it cannot forge a malformed LSP header. The parameter is typed
(`editapply.Language`), and the function's own comment explains that this is the enforcement: there
is no way to reach it except through the one table that produces the type, so a language cannot be
spelled and therefore cannot be misspelled.

**NEGATIVE RESULT: the inversion is withdrawn. LSP does not outrank MCP on reachability.** The
attacker would need to control the `PATH` or plant a binary under one of three fixed names — which is
a different and much larger precondition than "author a file in the repository".

### What the retraction does not cover — TB7 hardening row

`daemon/lsp_bridge.go:491`, inside `readHeaders`:

```go
line, err := out.ReadString('\n')
```

It bounds **neither a single header line nor the number of header lines**. `maxLSPMessageBytes` is
checked *after* the loop and applies to the declared body length only, so a server that emits one
unterminated header line, or unbounded header lines, exhausts memory before any cap is consulted.

| | |
|---|---|
| **Row** | R1.24 / TB7 — unbounded read in the LSP header loop |
| **Severity** | hardening, not urgent — reachability is low for the reason above |
| **Trigger** | *any* of: a language server becomes user-configurable by name or path; a server is resolved from workspace-relative `PATH`; a fourth language is added whose server is not a fixed name; or the bridge is pointed at a socket/remote rather than a spawned child |
| **Fix shape** | wrap the reader in `io.LimitReader` and cap the header-line count; both bounds are constants, and the body cap already exists to copy |
| **Not fixed here** | the chunk says record it, not fix it |
