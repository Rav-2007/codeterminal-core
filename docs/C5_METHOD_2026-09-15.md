## Part 1 — the gate that checked one file extension

### What it cost, retroactively

`scripts/docs-coderefs.sh` extracted references with a pattern ending in `\.go:`. Every `.ts`, `.yml`,
`.js`, `.sh` and `.md` citation in every enforced document **had never been checked** — measured both
ways in C4: a throwaway document carrying references to line 99999 of the extension's TypeScript, the
build workflow and a shell script passed at **exit 0**, while one bad Go reference failed at **exit 1**.

**The consequence is retroactive and it is the part worth stating.** C1b enforced
`docs/TRUST_BOUNDARIES.md` and reported it as enforced. Its Go anchors were checked; its TypeScript
and workflow anchors were not. **"This document is enforced" meant less than it said** — and nothing
in the output hinted at the gap, because a gate that reports only what it found looks identical to a
gate that found everything.

**53 citations had never been checked, across five extensions.**

### Derived, not listed (H10)

The chunk said *"extend it to every extension its documents actually cite"* and the prelude says an
instruction that names paths is a smell. **So no extension is named anywhere in the gate.** The
pattern matches any extension that begins with a letter — which is what keeps `10.0.0.1:8080` and
`v1.2.3:4` out — and the set that gets checked is whatever the documents cite. Naming the extensions
to add would have repeated the defect one generation later: the next document to cite a `.toml` or a
`.sql` would be unchecked again, and invisible in exactly the same way.

**The banner prints the derived set**, plus what the gate does not check:

```
docs-coderefs: 184 reference(s) resolve, across 17 enforced document(s); 253 reference(s) in 17 unenforced document(s) NOT checked
docs-coderefs: extensions checked (derived from the citations themselves): go,js,md,sh,ts,yml
docs-coderefs: NOT checked -- prose, anchors, section numbers, and any citation written without a :line suffix
```

A gate whose scope is invisible is how this one checked `.go` for its entire life.

### The new failure, and it was a real one

Widening found **one** broken citation **(M)**:

```

  -- .cursor/skills/.../SKILL.md is not a tracked file; CI cannot resolve it
```

`.cursor/skills/.../SKILL.md` used a **literal ellipsis** — readable for a person, unresolvable for
anything else. The file is tracked and the claim is correct: line 29 of
`.cursor/skills/enterprise-qa-master/SKILL.md` is the template placeholder the row describes.
**Fixed the citation, not the gate** (`d889120`), in its own commit before the gate landed so no commit
is transiently red.

## Part 2 — `scripts/reach.sh`

### Why it exists

> *"Every audit of the work passes each time. Only an audit of reach finds them, and no gate here
> measures reach."*

Seven instances, each found by accident. The seventh was found during C4b, four hours before this
gate was written: `0925a3d` repairs the failure that killed the **only release run this repository has
ever had**, and is not on `main`.

### Four checks

| # | Check | The instance it is shaped to |
|---|---|---|
| 1 | a local branch ahead of its upstream | 40 commits on a stale local ref |
| 2 | a branch with **no upstream at all** | `ca96966` — and check 1 is structurally blind to it |
| 3 | commits touching `.github/` or `scripts/` not on `main` | `142e57d`, `0925a3d` |
| 4 | enforced documents citing commits absent from `main` | the citations that point at nothing |

Check 2 exists because check 1 **cannot** see it: "ahead of upstream" is not computable when there is
no upstream. A gate that can only see what it can measure is the defect, not the gate — the same
`(b)`-direction reasoning `gate-parity.sh` was built on.

### The first run produced 213 failures, and that number changed the design

213 failures were **213 restatements of one fact**: this branch has not been delivered. An allowlist
with 213 entries is not a record of decisions, it is a way to stop reading.

**A commit's reach failure is subsumed by its branch's.** So an allowlisted branch entry, with its one
reason, accounts for the commits on it — and anything the branch does not explain is still reported
on its own. **213 → 10** **(M)**, with no loss of detection: removing the branch's entry brings all 50
pipeline commits straight back (measured in the neuter).

### The instruction's command was wrong, and the difference was measurable

The chunk specified `git cherry -v upstream/main HEAD -- .github scripts`. Measured **(M)**:

| Command | Count |
|---|---|
| `git cherry -v upstream/main HEAD` (no pathspec) | 240 |
| `git cherry -v upstream/main HEAD -- .github scripts` | **43** |
| `git rev-list --no-merges --count upstream/main..HEAD -- .github scripts` | **50** |
| `git log --no-merges --cherry-pick --right-only ... -- .github scripts` | **50** |

`git cherry` does accept the pathspec — **my first reading that it ignored the pathspec was wrong and
is retracted** — but it disagrees with the other two by seven commits. Since `upstream/main` is a
strict ancestor of HEAD (0 behind), patch-id equivalence is not in question here and **50 is the
answer**. `--cherry-pick --right-only` is used because it computes patch-id equivalence *restricted to
the pathspec*, which is the question being asked, and it stays correct if the branches ever diverge.

### Two findings from its own first run

Neither was previously known **(M)**:

1. **Seven branches — including `main` — track `origin`, which is the fork.** A bare `git push`
   delivers to a remote the pipeline does not watch. This is plausibly the *mechanism* underneath
   several of the seven delivery-gap instances, and no document in the repository names it.
2. **Two branches have no upstream at all:** `feat/canonical-language-table` (487 commits) and
   `feat/edit-payload-ingestion` (486).

The wrong-remote check is keyed `remote:<branch>`, **not** by branch name, so a branch that is
deliberately in flight cannot have its wrong-remote fact silenced by the in-flight reason. *Two facts
about one branch must not share one exemption* — M5, applied to the allowlist itself. Measured: with
`audit/adversarial-pass` allowlisted as in-flight, its wrong-remote finding still fires **(M)**.

which two it misses, and says why.

### `gate-parity` refused to let me skip the placement decision

Adding the script made `gate-parity.sh` fail on its own `(a)` direction **(M)**:

```
FAIL  reach.sh exists in scripts/ but has no entry in gate-parity.sh's manifest.
      A new check that nobody decided the placement of is how the two sides drifted.
```

Recorded as **`manual`**, with the reason in the manifest. It is not a gate yet because it reports 10
real findings today, so `make check` would be red on every local run and people would learn to skip it
— the reasoning that keeps `fuzz.sh` out. In CI it would be worse: a runner's clone has no local
branches, so checks 1 and 2 would examine nothing and **pass by being irrelevant**, which is exactly
the failure `hookcheck`'s exclusion names.

**The tension is stated, not hidden: a gate nobody runs is the delivery gap applied to the
delivery-gap gate.** The promotion condition is written into the manifest and is small — resolve or
allowlist those 10 findings and it moves to `local`.

## Part 3 — the method document

**Incumbent found first (H7).** `docs/ENGINEERING_METHOD.md` already exists, 283 lines, twelve
techniques and a five-shape failure taxonomy — distinct from `docs/RESIDUAL_RISKS.md` and
`docs/OPEN_ITEMS.md`, which are registers. **Annotated, not rewritten**, per its own technique 10.

Added: H1–H10 each with its instance; the mandatory report header; the eleven M5 pairs; a **sixth
failure shape** (the delivery gap); the commit-the-requirement-first technique; a **candidate**
thirteenth trust boundary, filed and not added; and a plain statement of what cannot be mechanised.

### Would the rule have caught its own instance?

The check the chunk asked for, done honestly.

| Rule | Its instance | Would it have caught it? |
|---|---|---|
| H1 | §13 cited as evidence about itself | **Yes** — H1 forbids exactly that citation, and C4b found four wrong rows |
| H2 | seven instrument failures | **Yes for five.** The regex, the pipe status, the reference frame and the gate scope are all "test your instrument". **No for two**: the `for`-loop and the loop-shadowing bug were found by the output looking wrong, not by a rule |
| H3 | "32 dangling citations", true answer zero | **Yes** — the retraction was the report |
| H4 | C2's premise | **Yes** — it is why the false premise became the headline instead of a footnote |
| H5 | the CHUNK_SCRUB contradiction | **Yes** — it forced naming the owner rather than resolving it |
| H6 | "macOS is green" vs "macOS ran tests" | **Yes** — the job log settled it and the inference would not have |
| H7 | `B<n>` meaning four things | **Yes, and again today**: it caught `M5` already meaning a Lane B threat row |
| H8 | neutering before committing | **Partly. It failed as a written rule twice**, which is why it is now a mechanical precondition. The *restore check* caught it both times, so the rule that worked was the check, not the sentence |
| H9 | the hedged macOS claim | **Yes** — the hedge is the tell |
| H10 | two enumerated instructions | **Yes, twice**, and both times the derivation was strictly better |

**H8 is the instructive row.** It is the only rule that had already been written down when its instance
occurred, and it did not hold — twice. **A rule that depends on remembering is not a rule.** What
worked both times was a mechanism: the restore check, which is why it stays even now the precondition
is enforced.

### What cannot be enforced, stated plainly

**H1, H3, H4, H5, H6, H7, H9 and H10 cannot be gated.** They are judgements about evidence, and no
gate can ask whether you looked. H2 is partly mechanisable — a gate can print its own scope, which
`docs-coderefs` now does — but it cannot test *your* instrument. H8 and the delivery gap are the only
two that became code.

**Calling a convention a gate would be the exact M5 error this repository keeps finding**, so the
method document says so in a table rather than implying enforcement.

Two structural limits recorded there: the documentation gates are `.md`-only, so a rule written in a
Go doc comment is checked by nothing; and `docs-coderefs` resolves every citation against `HEAD`, so a
citation to another revision's line numbers is silently validated against the wrong file. **Name the
revision in prose — no gate will catch it.**

## Self-corrections

1. **"`git cherry` silently ignores the pathspec" — wrong, retracted.** It accepts it and returns 43;
   the disagreement with `rev-list`'s 50 is a real discrepancy, not an ignored argument. I said the
   stronger thing before counting both.
2. **My neuter harness mislabelled all six extension rows.** The inner loop inside the fixture helper
   reused the outer loop's variable name, so every row printed `md`. The rows each named their own
   file, so the measurement survives — but **the instrument had a bug and the labels were wrong**, H2
   applied to a shell loop.
3. **A `grep` pattern missed an apostrophe** and I recorded arm 1 of the reach neuter as not firing.
   It had fired: the text is `branch 'zz-ahead' is 241 commit(s) ahead`, and my pattern was
   `zz-ahead is`. Re-ran and confirmed before writing the table.
4. **An empty probe commit landed on the working branch.** A `git commit --allow-empty` ran before the
   intended `git checkout -b`, putting `zz probe` on `audit/adversarial-pass`. Found by checking
   `git rev-parse --short HEAD` against the expected SHA during cleanup, removed with `git reset
   --hard`, and the branch verified back at the right commit. **H8's precondition is what makes this
   findable** — the arm began from a known-clean tree, so any drift was attributable.
