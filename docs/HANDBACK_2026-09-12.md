## 6. What a green CI run promises now, and what it still does not

*(This is 8.6's answer, current. The previous answer to this question was an
impression; this one is the matrix.)*

### It now promises, which it did not before 2026-09-12

- **The linters actually ran.** Six red `lint` jobs on `34314941707` reported
  nothing about lint — `Install linters` failed and `Lint` never executed,
  showing as `-` rather than red. Pinned versions and a `GOTOOLCHAIN` floor fixed
  it; the `Lint` step on `34678287938` is `success`.
- **The same tool versions a developer has.** `scripts/tool-pins.txt` is read by
  the CI installer *and* by `lint.sh`, which now checks the binary's version
  rather than only its presence.
- **The same Go patch version.** `GO_VERSION` was `1.25.x`, resolving to
  `go1.25.14` against seven files pinning `1.25.13`. It is now exact, and
  `go-toolchain-pinned.sh` checks the runner as an eleventh pin site.
- **A result computed from this commit.** `-count=1` on both sides; the test
  cache no longer makes a verdict a function of previous runs.
- **That `make check` and CI check the same things**, or that every difference is
  stated in code — `scripts/gate-parity.sh`, which fails on a **deletion**, not
  only an addition.
- **What each platform did not compile.** daemon reported
  `153 of 178 test files compiled; 25 DID NOT RUN` on `windows/amd64`. That block
  was silent before.
- **That the sandbox refusal message is the one for the host it is on**, rather
  than the one for a relaxed host.

### It still does not promise

- **That the sandbox confines anything on a normal host.** The confinement tests
  need a user namespace CI enables for itself (R1.27).
- **Anything about `helper` on Windows or macOS.** CGO makes it uncompilable
  there by any gate (R1.26). This cannot be closed, only stated.
- **macOS beyond `clients/tui`**, and the full `cross` matrix only on `main`.
- **That timing assertions are stable.** *(Deliberately conservative.)* daemon's
  17 bounds are no longer inline literals — each names the quantity it was
  derived from, and a static guard fails if a new bare literal appears. **That is
  auditability, not stability.** A guard against new inline literals does not make
  the existing seventeen stable: none has run on a loaded shared runner, and the
  guard cannot check whether a derivation is the *right* one, only that one is
  named. R1.28 is **narrowed, not closed**, and states four residuals.
- **That a green run reproduces on a developer's machine.** `make check` still
  cannot run Windows, macOS, docker or the Extension Development Host — which is
  why it now prints what it did not cover.
- **That anything at HEAD is built**, when HEAD is markdown-only.
