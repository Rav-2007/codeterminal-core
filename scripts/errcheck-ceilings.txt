# Per-module ceilings on UNCHECKED ERRORS outside tests (errcheck -ignoretests).
#
# These are grandfathered counts, not targets. The point is that they may not
# GROW: debt item (j) deferred errcheck adoption for sound reasons, but the
# deferral had no mechanism and the count drifted from 157 to 170 in two weeks.
#
# Lower a number whenever triage removes a site -- the script FAILS on a count
# below its ceiling, so a ratchet that has slackened is reported rather than
# quietly tolerated. Raising one is a decision that belongs in a commit message.
#
# 2026-08-01: daemon 111 -> 108, editapply 12 -> 10. The remediation pass added
# seven new unchecked sites and the ratchet caught every one. Rather than
# grandfather them, each was made explicit -- and so were the pre-existing
# neighbours they sat beside, because half a function using `_ =` and half not
# is worse than either. Net: fewer unchecked errors than before the pass, which
# is the direction these numbers are supposed to move.
#
# 2026-08-02: daemon 108 -> 107. The transport seam gave reclaimStaleSocket a
# second probe branch (a named pipe leaves no filesystem residue, so "stale"
# there means only "nothing answers"), which added one unchecked Close. Rather
# than grandfather it, both probe closes were made explicit with the reason --
# the probe has already answered the only question asked -- so the count went
# down rather than up.
#
# 2026-08-02: editapply 10 -> 9. Splitting applylock.go per platform for the
# Windows port moved the flock release into unlockFile, and the new call is
# explicit where the old inline one was not. The ratchet reported the SLACK
# rather than ignoring it, which is the half of a two-directional ceiling that
# usually goes unappreciated: an unclaimed improvement is how a ceiling drifts
# back up unnoticed later.
#
# 2026-08-06: daemon 107 -> 108, AUDITED AND ACCEPTED, recorded here so the next
# reader does not repeat the archaeology.
#
# The +1 cannot be attributed to a line, and that is a fact about the trees, not
# a gap in the review. 107 was measured on perf/latency-baseline; 108 is measured
# on this branch; and the commit between them (3bb9857) is the one whose whole
# purpose was to make the tree COMPILE AGAIN -- 3bb9857^ fails to build
# (protocol.HandshakeRequest.BearerToken and three siblings do not exist yet), so
# errcheck cannot produce a baseline there to diff against. Two measurements, no
# comparable tree in between.
#
# So the number was audited by category instead, which is the question that
# actually matters. All 108 are conventional discards:
#
#   ~25  enc.Encode(...) to a socket whose peer may already be gone
#   ~30  defer f.Close() on a handle opened for reading
#   ~25  fmt.Fprintf(out, ...) to stdout in the CLI
#   ~12  os.Remove(...) on a cleanup path that has already failed
#     6  fset.Parse(args) -- every FlagSet here is flag.ExitOnError, so Parse
#        calls os.Exit(2) rather than returning; checking it is unreachable
#     1  filepath.WalkDir(...) whose callback never returns a non-nil error
#
# None is a latent bug, so none was "fixed" to walk the number back down.
# Forcing a ceiling down by editing correct code is the same failure as raising
# a coverage floor to make a build green -- it moves the metric and teaches the
# ratchet to lie. The ceiling is honest at 108.
# 2026-08-12: daemon 108 -> 96. D8 founder ruling authorized the deletion of
# the dead skills subsystem (skills.go, skills_cmd.go). Removing 12 unchecked
# error sites lowered the ceiling automatically. Ratcheted to 96.
# 2026-08-12: daemon 96 -> 95. Phase 4 pruneWorkspace clock-injection changed
# one call site from time.Now() (unchecked) to a parameter, removing one
# unchecked site.
#
# 2026-08-26: daemon 95 -> 92. The incremental-indexing pass rewrote the lexical
# store's two write paths (chunk_index, see lexicalstore.go). Its prepared
# statements and both transaction rollbacks are explicit `_ =` discards rather
# than the bare calls the old code used -- a rollback after a successful commit
# is a no-op by definition, and a prepared statement's Close has already had its
# only interesting failure reported by the Exec that used it. The bare
# `defer tx.Rollback()` that Upsert inherited was converted with them, on this
# file's own rule that half a function marking its discards and half not is worse
# than either. Net -3, claimed here rather than left as slack.
